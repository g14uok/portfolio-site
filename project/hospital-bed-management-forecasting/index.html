Hospital Bed Management & Forecasting

Combines real-time patient events and batch bed-configuration data to support hospital bed visibility and capacity forecasts.

HL7AWS KinesisAirflowPostgreSQLARIMA

High-Level Summary

This hospital-operations platform combines real-time HL7 events with batch bed-configuration data to support inpatient bed visibility and forecasting. I contributed streaming and batch data pipelines, historical snapshots, and ARIMA-based capacity forecasting.

The Challenge

Hospital bed state and patient movement change continuously, while configuration and historical context arrive through separate data processes. The system needed both timely event processing and durable history to support operational analysis and forecasts.

Architecture & System Overview

HL7 patient events are processed through a streaming path, while Airflow jobs ingest bed configurations and create historical snapshots. The resulting data supports bed-state analysis and ARIMA time-series forecasts of inpatient availability.

Key Engineering Trade-offs & Lessons

  • Combining streaming and batch processing provides freshness and historical context, but requires reconciliation across both paths.
  • Historical snapshots make trend analysis possible while increasing storage and data-quality responsibilities.
  • Forecasts complement operational visibility; they should not be treated as substitutes for hospital staff judgment.
