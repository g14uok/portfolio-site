Privacy-Aware LLM Customer Support

Routes general questions to public knowledge sources and account-specific requests to authenticated customer-data paths.

LLMsRAGPythonAWSData Access

High-Level Summary

This customer-support system classifies incoming questions and routes them to either a general knowledge workflow or an account-specific data path. I contributed to a design that keeps general retrieval separate from authenticated access to private customer information.

The Challenge

A support assistant must answer common questions efficiently without treating private account data as ordinary public knowledge. The system needed to distinguish question types and apply the correct access path before generating a response.

Architecture & System Overview

The request first passes through authentication and query classification. General questions use a retrieval-augmented generation path over approved knowledge sources, while customer-specific questions are routed to the corresponding authorized data path.

Key Engineering Trade-offs & Lessons

  • Separate request paths make privacy boundaries clearer, at the cost of additional routing and authorization logic.
  • The system treats access control as part of request handling rather than relying on the language model to infer permissions.
  • Retrieval quality depends on curated knowledge sources, and the account-specific path must remain separate from general retrieval.
